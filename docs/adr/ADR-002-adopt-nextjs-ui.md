# ADR-002: اعتماد Next.js لتحديث واجهة المستخدم (Adopt Next.js for UI Modernization)

- **الحالة (Status):** مقبول (Accepted)
- **التاريخ (Date):** 2026-10-11
- **أصحاب القرار (Decision Makers):** @djalle2004-eng
- **المشاورون (Consulted):** فريق تجربة المستخدم وهندسة الويب

---

## 1. السياق والمشكلة (Context & Problem Statement)
واجهة المستخدم الحالية مبنية على حزمة React 18 + Vite مدمجة داخل Electron كـ SPA ضخم يتجاوز 4.2 ميغابايت للملف الرئيسي (`index.js`). هذا يسبب:
- بطء في زمن التحميل الأولي للأساتذة والطلبة عبر شبكات الهاتف المحمول في الحرم الجامعي.
- صعوبة في التقديم المسبق على الخادم (SSR / SSG) لجداول التوقيت العامة التي لا تحتاج إلى تسجيل دخول.
- تداخل منطق التوجيه بين إلكترون والمتصفح.

## 2. المحركات المعمارية (Decision Drivers)
- تحسين سرعة العرض الأولي (First Contentful Paint) لجداول الحصص.
- دعم الصفحات العامة الثابتة (Public Timetables) مع التحديث المتزايد (ISR).
- الاستفادة من React Server Components لحماية منطق الأعمال الحساس وتقليل حجم حزم JavaScript المرسلة للمتصفح.

## 3. الخيارات المدروسة (Considered Options)
1. **البقاء على Vite SPA الحالية:** استقرار ممتاز ومختبر، لكنه يعاني من حجم الحزمة الكبير وانعدام الـ SSR.
2. **الترقية إلى Next.js 14+ مع App Router (المعتمد):** دعم ممتاز للـ SSR وISR، والتكامل السلس مع Vercel وNode.js وDocker.
3. **التحول إلى Remix:** خيار ممتاز لمعالجة النماذج، لكن منظومة الدعم والمكونات العربية RTL أوسع في Next.js.

## 4. القرار المعتمد (Decision Outcome)
بناء واجهة الويب الحديثة (V2) داخل مساحة عمل `apps/web-next` بالاعتماد على **Next.js 14 App Router** مع الاحتفاظ بتطبيق Vite الحالي (`apps/web`) نشطًا بنمط Strangler Fig حتى اكتمال النقل الوظيفي.

### الآثار الإيجابية (Positive Consequences)
- خفض حجم حزمة العرض الأولي لجداول التوقيت بأكثر من 70%.
- إتاحة روابط سريعة للطلبة للاطلاع على جداول الأفواج والقاعات دون الحاجة لتحميل التطبيق الكامل.
- سهولة دعم التدويل الكامل (Arabic RTL / French) على مستوى الخادم.

### الآثار السلبية والمخاطر (Negative Consequences / Trade-offs)
- الحاجة للحفاظ على واجهتين خلال فترة الانتقال.
- إدارة الجلسات ومصادقة JWT بين Express وNext.js.

## 5. خطة التنفيذ والرجوع (Rollout & Rollback Strategy)
- تشغيل تطبيق Next.js على نطاق فرعي أو خلف مسار `/v2/` مخصص.
- التوجيه يتم عبر خادم وكيل (Reverse Proxy)؛ وأي خلل يُعاد فورًا إلى تطبيق Vite القديم عبر تعديل توجيه بسيط دون مساس بالنظام الأساسي.
