# وثيقة تحديث نموذج الهوية والمصادقة (P4 Identity & Authentication Specification)

## 1. ملخص المعمارية ونموذج التهديد (Threat Model)

قبل هذا التحديث، كان النظام يعتمد على:
1. **تجزئة bcrypt القديمة بتكلفة 10** المعرضة لهجمات المعالجات الرسومية المتوازية (GPU/ASIC cracking).
2. **رموز JWT ثابتة بمدة 7 أيام** دون وجود سجل جلسات في قاعدة البيانات، مما كان يجعل إبطال الجلسة الفوري مستحيلاً عند سرقة جهاز المستخدم.
3. **تسريب رمز الاستعادة (SEC-04):** كان مسار `/auth/forgot-password` يُرجع `debugToken` في بيئة التطوير، مع تباين في الاستجابة يكشف وجود الحسابات.
4. **تسجيل مفتوح بلا دعوات (SEC-08):** كان بإمكان أي شخص تسجيل حساب برتبة أستاذ مباشرة.
5. **غياب المصادقة متعددة العوامل (SEC-10):** عدم وجود حماية 2FA لحسابات المشرفين والمسؤولين.

## 2. دروع الأمان والتعديلات المنفذة (Implemented Defenses)

### أ. التجزئة المتقدمة بـ Argon2id والترحيل الشفاف التدريجي (Zero-Downtime Hash Migration)
* **معاملات التجزئة المعتمدة عالمياً:**
  * الذاكرة: **19 MiB** (`ARGON2_MEMORY_COST=19456`).
  * الدورات: **2** (`ARGON2_TIME_COST=2`).
  * التوازي: **1** (`ARGON2_PARALLELISM=1`).
* **التحقق المزدوج الذكي (Dual-Verification):**
  * إذا كانت التجزئة تبدأ بـ `$argon2id$`، يتم التحقق بمحرك Argon2id.
  * إذا كانت التجزئة تبدأ بـ `$2a$` أو `$2b$` (bcrypt القديم)، يتم التحقق بمحرك bcrypt.
* **الترقية التلقائية عند الدخول:** فور تسجيل دخول المستخدم بكلمة مرور bcrypt صحيحة، يعيد الخادم فوراً تجزئتها بـ Argon2id ويحدث قاعدة البيانات آلياً في الخلفية دون الحاجة لإجبار المستخدمين على إعادة تعيين كلمات مرورهم، ودون توقف النظام.

### ب. رموز قصيرة وجلسات قابلة للإبطال (15m Access Token & 30d Refresh Session)
* **رمز الوصول (Access Token):** مدته **15 دقيقة** فقط مع ترويسة `kid: v2`.
* **رمز التجديد (Refresh Token):** مدته **30 يومًا**، مُولَّد عشوائياً بتشفير 48 بايت، ويُخزن في جدول `sessions` مُمشَّفاً بـ **SHA-256** فقط.
* **التدوير عند كل استخدام (Token Rotation):** عند كل طلب تجديد، يُبطل الرمز القديم ويُصدر رمز جديد فوراً.
* **كشف إعادة الاستخدام والحماية من السرقة (Reuse Detection - SEC-01):**
  إذا حاول مهاجم استخدام رمز تجديد تم استخدامه مسبقاً (مُلغى)، يكتشف النظام الهجوم فوراً ويقوم **بإلغاء كافة جلسات المستخدم النشطة تلقائياً** ويسجل حدث `TOKEN_REUSE_DETECTED_ALL_REVOKED` في سجل التدقيق الأمني.

### ج. إغلاق تسريب الرموز والاسترجاع الآمن (Safe Password Recovery - SEC-04)
* **حذف `debugToken` نهائياً:** لا يظهر أي رمز استرجاع في أي استجابة برمجية، سواء في التطوير أو الإنتاج.
* **استجابة موحدة (Uniform Response):** يُرجع المسار دائماً:
  ```json
  { "success": true, "message": "إذا كان البريد الإلكتروني مسجلاً، فستصلك تعليمات استعادة كلمة المرور." }
  ```
  لمنع تعداد واكتشاف الحسابات المسجلة (Account Enumeration).
* **صلاحية الرمز:** الرمز صالح للاستخدام **لمرة واحدة فقط** وبمدة قصوى **15 دقيقة**، ويُخزن مُمشَّفاً بـ SHA-256 في جدول `password_reset_tokens`.
* **إلغاء الجلسات عند التغيير:** عند إتمام إعادة تعيين كلمة المرور بنجاح، تُبطل جميع جلسات المستخدم القديمة فوراً.

### د. نظام الدعوات الرسمية بدلاً من التسجيل المفتوح (Invitations Flow - SEC-08)
* **إغلاق التسجيل الحر:** تم تعطيل مسار `/auth/signup` المفتوح خلف علم `FEATURE_OPEN_SIGNUP=false`.
* **إنشاء الدعوة:** مقتصر على الإداريين عبر مسار `POST /auth/invitations`.
* **قبول الدعوة:** يتم عبر `POST /auth/accept-invitation` مع التحقق من الرمز المُمشَّف وتوثيق وقت تأكيد البريد في الحقل الجديد `email_verified_at`.

### هـ. المصادقة الثنائية بـ TOTP (RFC 6238 MFA - SEC-10)
* **دعم التطبيقات المعتمدة:** متوافق بالكامل مع Google Authenticator و Microsoft Authenticator.
* **أكواد الاسترجاع للطوارئ:** إصدار **10 أكواد استرجاع أحادية الاستخدام** تُخزن مُمشَّفة للرجوع إليها في حال فقدان الهاتف.
* **تفعيل اختياري متدرج (Red Line 4):** الـ 2FA متاح وفعال اختياريًا لحين إثباته والتأكد من حفظ الإداريين لأكواد الاسترجاع.

### و. القفل التدريجي وسجل التدقيق الأمني (Brute-Force Lockout & Audit Trail)
* **القفل التدريجي:** بعد **5 محاولات فاشلة** خلال 15 دقيقة، يُقفل الحساب/عنوان IP مؤقتاً لمدة **15 دقيقة**.
* **جدول `auth_events`:** يسجل كافة الأحداث الأمنية (تسجيل دخول، فشل دخول، تدوير الرموز، كشف إعادة الاستخدام، تفعيل وإلغاء 2FA).

## 3. المخطط التوسعي لقاعدة البيانات (Expand-Only Schema)

التزاماً بميثاق **«لا شيء يُكسر ولا شيء يُحذف»**، كافة التعديلات في المخطط هي إضافات فقط:
* `sessions`: إدارة الجلسات والأجهزة والتجديد.
* `auth_events`: سجل الأحداث والتدقيق الأمني.
* `invitations`: إدارة الدعوات المعتمدة.
* `mfa_factors`: تخزين مفاتيح TOTP وأكواد الطوارئ المُمشَّفة.
* `password_reset_tokens`: تخزين رموز الاستعادة المُمشَّفة.
* `users.email_verified_at`: حقل توثيق البريد الإلكتروني (nullable).

## 4. رايات الميزات وخطة الرجوع (Feature Flags & Rollback Plan)

| المتغير | القيمة الافتراضية | الوصف وخطة الرجوع |
| :--- | :--- | :--- |
| `FEATURE_NEW_AUTH` | `true` | محرك الهوية المطور. إطفاؤه يعيد التحقق إلى النمط الكلاسيكي. |
| `FEATURE_OPEN_SIGNUP` | `false` | إغلاق التسجيل المفتوح. تفعيله يعيد فتح التسجيل العام إن لزم الأمر. |
| `FEATURE_MFA` | `true` | تفعيل دعم المصادقة الثنائية TOTP لحسابات المشرفين. |
| `ARGON2_MEMORY_COST` | `19456` | حجم الذاكرة المخصص لـ Argon2id (19MiB). |
| `ARGON2_TIME_COST` | `2` | عدد تكرارات خوارزمية Argon2id. |

**خطة الرجوع عند الطوارئ:**
كافة التغييرات في قاعدة البيانات إضافية تماماً ولا تؤثر على الجداول القديمة. لتعطيل متطلبات الدعوة، يكفي ضبط `FEATURE_OPEN_SIGNUP=true`.
