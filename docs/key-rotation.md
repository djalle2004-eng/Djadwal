# دليل تدوير المفاتيح الأمنية بلا انقطاع (Zero-Downtime Key Rotation Guide)

> **المبدأ الحاكم:** «لا شيء يُوقف، ولا جلسات تُفقد».
> يُمنع إجبار الأساتذة أو الإداريين على تسجيل خروج جماعي مفاجئ أثناء تدوير المفاتيح. تتم عملية التدوير باتباع استراتيجية التوافق المزدوج (Dual-Key Verification) مع رأس `kid`.

---

## 1. تدوير مفتاح توثيق الجلسات (JWT_SECRET)

تستخدم منظومة Djadwal رموز JWT صالحة لمدة 7 أيام. عند الرغبة في تدوير المفتاح المشفر:

### المرحلة 1: إنشاء المفتاح الجديد
قم بتشغيل سكربت التدوير الآلي لتوليد مفتاح عشوائي 256-bit والتحقق من صحة التوافق المزدوج:
```bash
npx tsx scripts/rotate-jwt-secret.ts
```

### المرحلة 2: تفعيل وضع المفتاحين المتزامنين (Dual-Key Mode)
في لوحة تحكم الخادم (Render Dashboard -> Environment Variables):
1. انسخ القيمة الحالية لـ `JWT_SECRET` وضعها في متغير البيئة الجديد:
   ```env
   JWT_SECRET_PREVIOUS=<القيمة القديمة>
   ```
2. ضع المفتاح المولد حديثًا في:
   ```env
   JWT_SECRET=<القيمة الجديدة بطول ≥ 32 حرفًا>
   ```
3. أعد نشر الخادم (Trigger Manual Deploy).

#### كيف يعمل النظام خلال هذه المرحلة؟
- **الجلسات القائمة:** عندما يرسل مستخدم رمزًا قديمًا، يفشل الفحص بالمفتاح الرئيسي الجديد تلقائيًا، فينتقل النظام فورًا للفحص بالمفتاح الاحتياطي `JWT_SECRET_PREVIOUS`. يقبل الرمز ويبقى المستخدم مسجلاً.
- **الجلسات الجديدة:** أي تسجيل دخول جديد يتم توقيعه فورًا بالمفتاح الرئيسي الجديد `JWT_SECRET`.

### المرحلة 3: اختتام التدوير وحذف المفتاح القديم
بعد مرور 7 أيام (وهي أقصى مدة لصلاحية الرموز القديمة)، تكون كافة الجلسات النشطة قد تم تجديدها بالمفتاح الجديد تلقائيًا:
1. احذف متغير `JWT_SECRET_PREVIOUS` من لوحة التحكم أو اتركه فارغًا.
2. أعد النشر. الآن يعمل النظام بالمفتاح الجديد بنسبة 100%.

## 2. تدوير رمز مصادقة قاعدة البيانات السحابية (TURSO_AUTH_TOKEN)

يتم تدوير رمز مصادقة Turso بالاستفادة من دعم Turso لتعدد الرموز المميزة لكل قاعدة بيانات:

### الخطوة 1: استخراج رمز جديد من واجهة Turso CLI
```bash
# إنشاء رمز جديد للقاعدة
turso db tokens create Djadwal --expiration none
```

### الخطوة 2: اختبار الرمز الجديد في بيئة Staging
1. عيّن `TURSO_AUTH_TOKEN` الجديد في بيئة المعاينة (Staging Docker).
2. قم باستدعاء فحص الصحة `/api/status` واختبر قراءة جدول الأقسام:
   ```bash
   curl http://localhost:5050/api/status
   ```
3. تأكد من أن الاتصال بالقاعدة سليم بنسبة 100%.

### الخطوة 3: تحديث بيئة الإنتاج على Render
1. ادخل إلى إعدادات خدمة `djadwal` على Render.
2. حدّث قيمة `TURSO_AUTH_TOKEN` بالقيمة الجديدة.
3. اضغط **Save Changes** لإعادة تشغيل الحاويات تدريجيًا (Rolling Restart) دون انقطاع الاتصال.

### الخطوة 4: إلغاء صلاحية الرمز القديم (Revocation)
بعد التأكد من استقرار خوادم الإنتاج لمدة 24 ساعة ونجاح كافة عمليات القراءة والكتابة:
```bash
# استعراض الرموز القديمة
turso db tokens list Djadwal

# إبطال الرمز القديم غير المستعمل
turso db tokens revoke <OLD_TOKEN_ID> Djadwal
```

---

## 3. مصفوفة التحقق الأمني من الرموز (Checklist)

- [ ] تم التحقق من طول `JWT_SECRET` الجديد (≥ 32 حرفًا).
- [ ] تم اختبار فحص التوكن القديم بنجاح قبل حذف `JWT_SECRET_PREVIOUS`.
- [ ] لم يُطبع أي رمز أو سر في السجلات المباشرة أو ملفات Git.
- [ ] تم التحقق من سلامة فحص الصحة على المسار `/api/status` بعد كل تدوير.
